# Padlet Sender

웹 패널에서 **게시판 주소·게시물 개수·제목·내용·전송 간격**을 입력하고 실행하면, 서버가 선택한 작성 방식의 세션을 만들고 전송합니다. 기본은 비로그인이며 **쿠키 사용하기**를 체크하면 서버에 고정된 쿠키의 로그인 계정으로 작성합니다. 사용자의 Padlet 로그인 상태를 바꾸거나 수동으로 게시할 필요가 없습니다.

- 웹 패널: https://usernameofficial.github.io/padlet/
- 서버: https://padlet-sender-panel.onrender.com

## 사용 방법

먼저 디스코드 봇에서 키를 발급받습니다. 사이트의 키 입력 창에서 인증하면 자체 백엔드가 키를 검증한 뒤 임의 세션 토큰만 발급합니다. **키는 최초 인증 요청에만 포함되고, 이후 요청에는 세션 토큰만 사용합니다.** 브라우저 저장소에는 원본 키를 저장하지 않습니다. 최초 요청의 키는 본인의 개발자 도구에서 확인할 수 있습니다. [로컬 봇 설치·명령어·키 운영 안내](keybot/README.md)를 참고하세요.

봇은 `start-keybot.cmd`로 백그라운드 실행하며 CMD 창을 닫아도 유지됩니다. 키 기록은 Firebase Cloud Firestore에 저장하므로 로컬 봇이 꺼져 있어도 사이트 인증·차감·기한 검사·사용 로그가 동작합니다. 소진·만료된 키는 실행 버튼이 잠기고 서버도 새 실행을 거부합니다.

1. 인증 후 다섯 항목을 입력하고 **실행**을 누릅니다. 다회용 키는 새 실행 접수마다 1회 차감합니다.
2. 실행 현황에 작성 세션 준비, 전송 성공 수, 오류 사유가 표시됩니다.
3. **중지**는 준비 단계에서도 사용할 수 있습니다. 이미 전송 중인 요청은 결과를 받은 뒤 멈춥니다.
4. **긴급 삭제**를 누르면 전송을 멈추고, 진행 중인 게시 응답까지 확인한 뒤 **현재 패널 세션의 모든 실행에서 보낸 게시물**을 삭제합니다. 여러 게시판에 실행한 기록도 포함합니다. 삭제 대상·삭제 확인·오류 수를 화면에서 확인할 수 있고, 실패한 항목은 버튼을 다시 눌러 재시도할 수 있습니다. 429 요청 제한은 표시된 대기 시간이 지난 뒤 다시 시도하세요.

긴급 삭제는 생성 성공 응답의 게시물 hashid와 해당 실행의 작성 세션을 사용합니다. 다른 사람이 작성한 글이나 게시판 전체 목록을 삭제 대상으로 수집하지 않습니다. 삭제는 이 패널에서 복구할 수 없습니다. 성공 응답에 hashid가 없으면 ‘추적 불가’로 표시하고, 네트워크 오류로 생성 여부를 확인하지 못한 글도 자동 삭제를 보장하지 않습니다. 이 기능 추가 전에 보낸 글, 서버 재시작 전 기록, 만료된 패널 세션의 기록은 자동 삭제할 수 없습니다.

게시물 개수는 **섹션당 게시물 수**입니다. 매 주기마다 모든 섹션에 각각 1건씩 요청합니다. 예를 들어 섹션 3개, 개수 10, 간격 0.3초이면 0.3초마다 세 섹션에 1건씩, 총 30건을 전송합니다. 섹션이 없는 게시판은 주기당 1건입니다. 기본값은 섹션당 50건 / 0.3초이며 개수 0은 모든 플랜에서 무제한입니다. 영구 플랜 외에는 실행당 섹션별 개수를 최대 5,000개까지 지정할 수 있습니다. 영구 플랜의 기존 숫자 입력 상한(1,000,000개)은 유지됩니다. 모든 간격에서 앞선 회차의 응답을 기다리지 않고 다음 회차를 시작할 수 있습니다. 한 번에 진행하는 요청은 최대 32건이며, 섹션 1개면 최대 32회차, 3개면 최대 10회차를 겹쳐 처리합니다. 섹션이 32개보다 많으면 한 회차 안에서 최대 32건씩 처리합니다. 동시 처리 한도에 도달하면 응답을 기다리며, 밀린 회차를 만회하려고 설정 간격보다 짧게 몰아서 보내지는 않습니다. 0은 추가 대기 없는 최대 속도입니다. 실제 처리량은 Padlet 응답과 요청 제한에 따라 달라집니다.

전송·삭제 작업은 서버에서 진행되므로 웹 페이지를 닫아도 계속될 수 있습니다. 전송을 멈추려면 중지를 누르세요. 삭제 기록은 같은 탭을 새로고침해도 패널 세션이 유지되면 사용할 수 있습니다. 작업이 끝난 뒤 30분간 패널에 접속하지 않으면 세션이 만료됩니다. 서버 재시작·세션 만료 시 메모리의 작업·삭제 자격 정보·게시물 기록은 사라집니다.

## 작성 방식과 자동 준비

### 위장 화면

키 인증 후 메인 화면에 전송 설정을 입력하지 않고 오른쪽 위 **위장하기**를 누르면 제공된 Google HTML을 바탕으로 만든 정적 화면으로 이동합니다. 검색창에서 아래 형식을 입력하고 **Enter**를 눌렀을 때만 현재 인증 세션으로 실행합니다.

- 비밀번호 없음: `d, https://padlet.com/example/board, 제목, 내용, 10, 0.5`
- 비밀번호 있음: `d, https://padlet.com/example/board, board-password, 제목, 내용, 10, 0.5`

모든 명령에는 `d`(비로그인) 또는 `c`(고정 쿠키 사용) 접두어가 필수입니다. 쿠키로 작성하려면 위 예시의 `d`를 `c`로 바꾸세요. 메인 화면 체크 상태와 관계없이 접두어로 실행 방식을 결정합니다.

마지막 두 항목은 섹션당 게시물 개수와 작성 간격(초)입니다. 각 항목을 괄호로 감싸도 됩니다. 문구나 비밀번호에 쉼표가 있으면 큰따옴표로 감싸세요. 제목·내용 중 하나는 필수입니다. 일반 검색·링크·버튼은 동작하지 않으며 Google로 요청을 보내지 않습니다. 제목·내용·비밀번호는 검색창의 명령에서만 읽으며 브라우저 저장소에 저장하지 않습니다. 기존 키 인증·이용권 제한은 그대로 적용됩니다. 브라우저 **뒤로 가기**로 돌아와 실행 상태를 확인하거나 중지·긴급 삭제할 수 있습니다. 위장 화면으로 이동하거나 닫아도 진행 중인 작업은 멈추지 않습니다.

### 고정 쿠키 작성

사용자는 쿠키를 입력하지 않습니다. 메인 화면의 **쿠키 사용하기** 또는 위장 화면의 `c` 명령이 서버의 고정 쿠키를 사용합니다. 실행마다 새 브라우저에 쿠키를 주입하고, Padlet이 반환한 로그인 계정의 ID로 작성합니다. 쿠키가 없거나 로그인 상태를 확인하지 못하면 중단하며 익명으로 전환하지 않습니다. `d`는 항상 쿠키 없는 새 세션입니다.

관리자는 `PADLET_COOKIE_HEADER` 환경변수 또는 `PADLET_COOKIE_FILE`이 가리키는 비공개 파일로 쿠키를 설정합니다. 기본 파일은 `.local/padlet-cookie.txt`이며 Git 및 Docker 빌드에서 제외됩니다. 파일은 `이름=값; 이름2=값2` 헤더 값 또는 이름·값이 번갈아 나오는 텍스트 형식을 지원합니다. 배포 서버에는 별도 Secret File을 등록하고 경로를 지정해야 합니다. 원본 값은 웹 정적 파일·상태 응답·로그에 포함하지 않습니다. 삭제 기능은 해당 실행의 세션을 서버 메모리에 보관해 그 실행에서 작성한 글만 처리합니다. 쿠키 만료 시 관리자가 파일 또는 환경변수를 갱신해야 합니다.

### 커스텀 쿠키

기본 쿠키 설정은 유지됩니다. 패널에서 **쿠키 사용하기**와 **커스텀 쿠키 사용**을 켠 뒤 `이름=값; 이름2=값2` 형식으로 입력하고 **커스텀 쿠키 저장**을 누르면 해당 패널 세션의 `c` 명령과 쿠키 작성에 사용됩니다. **기본 쿠키로 되돌리기** 또는 커스텀 체크 해제로 복귀합니다. 쿠키 원문은 브라우저 저장소·상태 응답·로그에 넣지 않으며 서버 메모리의 패널 세션에만 보관합니다. 세션이 만료되거나 서버가 재시작되면 사라집니다. Padlet이 로그인 상태를 확인하지 못하면 작성하지 않습니다.

`ww_*` 쿠키의 개별 필수 조합은 공식적으로 확인되지 않았으므로 로그인된 Padlet 세션에서 필요한 쿠키를 헤더 형식으로 함께 입력해야 합니다. `__cf_bm`과 `cf_clearance`는 Cloudflare 보안 쿠키이며 Padlet 계정 인증을 대체하지 않습니다.

### 비밀번호 게시판

**비밀번호가 설정된 게시판**을 켜면 Padlet 비밀번호 입력란이 나타납니다.
Padlet의 초기 잠금 정보에 있는 제출 주소와 인증 토큰을 사용해 비밀번호를 한 번 제출합니다.
화면 입력란이 아직 생성되지 않아도 인증할 수 있으며, 선택한 작성 세션으로 게시글 권한을 확인합니다. 로그인 화면 입력이나 보안 확인 화면은 처리하지 않습니다.
비밀번호가 틀리면 작성하지 않고 종료합니다. 비밀번호는 상태 응답·로그·브라우저 저장소에
기록하지 않고, 실행 요청 후 입력란을 비웁니다. 별도 게시판 주소 제한은 없습니다.


## 구성과 배포

- `web/`: 다섯 입력란과 실행·중지·긴급 삭제·활동 로그 화면. GitHub Pages로 배포합니다.
- `server/app.py`: 세션·상태·실행·중지·긴급 삭제 API. `/api/run`과 `/api/emergency-delete`는 작업을 접수한 뒤 곧바로 응답합니다. 삭제 API는 클라이언트가 전달한 게시물 ID를 사용하지 않고 인증된 패널 세션의 기록만 처리합니다.
- `server/engine.py`: 익명 자동 준비, 매 주기 전체 섹션 동시 전송, 중지와 세션 정리.
- `server/browser.py`: 서버 내부 브라우저와 같은 출처의 요청 처리.
- `server/anonymous.py`, `server/fields.py`: 익명 상태·섹션·입력 항목 확인.
- 이전 연결·캡처 API는 현재 화면에서 사용하지 않습니다. 수동 브라우저 조작 API는 실행 횟수 차감을 우회할 수 있어 차단했습니다.

`main`의 `web/` 변경은 GitHub Pages 워크플로로 배포합니다. Render는 기존 `padlet-sender-panel` Docker 서비스를 사용합니다. Playwright 이미지와 Python 패키지 버전은 1.58.0으로 맞춥니다. 세션이 메모리에 있으므로 서버 worker와 인스턴스는 각각 하나로 유지합니다.

## 검증

```powershell
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python -m playwright install chromium
.\.venv\Scripts\python tests/ui_smoke.py
.\.venv\Scripts\python tests/automatic_smoke.py
.\.venv\Scripts\python tests/preparation_smoke.py
.\.venv\Scripts\python tests/disguise_smoke.py
.\.venv\Scripts\python tests/cookie_smoke.py
node --check web/app.js
```

서버 테스트와 Chromium 모의 통합 테스트로 한 번의 실행 요청, 익명 준비, 준비용 게시물 없는 전송, 매 주기 전체 섹션 동시 전송과 섹션당 개수, 익명·쿠키 작성의 계정 확인, 필수 항목 검증, 준비 중 중지와 리소스 정리를 확인합니다. 실제 게시판 검증에서는 생성 요청을 보내기 전에 차단하며 게시물을 작성하지 않습니다.
